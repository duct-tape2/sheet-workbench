Self-host an alpha

Copy the example environment, replace every placeholder secret, then start the app and PostgreSQL volume.

cp .env.example .env
docker compose up --build

Read the repository self-hosting and backup runbooks before exposing anything beyond localhost.

Before real data

  • Use one HTTPS origin for the browser and /api.
  • Keep PostgreSQL private and generate all secrets.
  • Get explicit permission to upload or connect a source.
  • Do not enable Google until OAuth, Picker, import, refresh, writeback, and conflict tests pass.

Current alpha limits

Native PostgreSQL has passed a local synthetic signup, XLSX, and backup/restore smoke test. Docker, public hosting, live Google, mail delivery, native Excel reopening, and a three-team pilot remain unverified. Owners can export a workspace archive, restore it as a new workspace, or delete a workspace after exact-name confirmation. Archives exclude members, auth rows, and Google credentials; restored Google sources are disconnected and read-only. Full database recovery still follows the operator runbook.

For a synthetic team trial without Docker, run npm run demo:team and open http://127.0.0.1:3002. This local-only trial supports signup and sample XLSX uploads. It stores data in .local/team-trial, disables Google connections, and is not a production server. Press Ctrl+C to stop it.

The current server reads GOOGLE_PICKER_DEVELOPER_KEY and GOOGLE_APP_ID. The OAuth scope is limited to drive.file; do not enable Google until live consent, Picker, import, refresh, writeback, and conflict tests pass.
