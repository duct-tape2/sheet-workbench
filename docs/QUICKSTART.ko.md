# 빠른 시작

이 안내는 현재 로컬 파일 리뉴얼부터 설명합니다. 관리형 클라우드 서비스가 아니라 로컬 알파 작업 흐름입니다.

## 1. 로컬 작업 공간 열기

Node.js `22.12+`와 npm이 필요합니다.

```sh
npm ci
npm run dev
```

<http://127.0.0.1:5173/?mode=local>을 엽니다. 현재 기본 모드가 로컬이므로 쿼리 값은 생략해도 됩니다. 이 경로에는 계정·데이터베이스·`.env` 파일·Google 계정·서버 설정이 필요하지 않습니다.

**파일 열기**를 고르세요. 가상 샘플로도 시작할 수 있지만, 샘플은 인터페이스를 안전하게 살펴보는 용도일 뿐 실제 통합 문서의 증거가 아닙니다.

## 2. 원본을 받기 전에 확인하기

`.csv` 또는 지원되는 `.xlsx` 파일을 고릅니다. 원본으로 받아들이기 전 가져오기 확인 화면을 검토하세요.

- XLSX: 시트, 제목 행, 첫/마지막 열, 마지막 행.
- CSV: 제목 행/범위, 인코딩, 구분자.
- 제목 행 앞에 안내 문구가 있거나 표준적이지 않은 제목을 쓴 파일이라면 표시된 행과 열.

범위가 맞을 때만 **원본 받아들이기**를 누르세요. 로컬 흐름은 원본 바이트를 브라우저 메모리에서 읽으며, 선택한 PC 파일을 덮어쓰지 않습니다.

현재 보호 한도는 원본 파일 합계 25MiB, 가져온 행 10,000개입니다. 지원하지 않는·암호화된·매크로 중심인·구형·모호한 구조의 통합 문서는 거부될 수 있습니다. 수식과 보호된 셀은 잠깁니다.

## 3. 작업 흐름 고르기

### 파일 하나 정리

파일을 기준 원본으로 둔 뒤 **작업** 패널에서 공백 정리, 빈 행 제거, 중복 제거, 찾기/바꾸기, 열 하나의 형식 변환, 요약을 사용합니다. **결과 확인**을 눌러 바뀐 행과 경고를 검토하세요. 막힌 미리보기는 적용할 수 없습니다.

### 들어온 행 이어붙이기

1. 두 파일을 모두 열고, 기존 표를 제공하는 파일을 기준 원본으로 고릅니다.
2. **원본 이어붙이기**를 고른 뒤 들어온 원본을 고릅니다.
3. 결과 대상 열마다 들어온 열을 명시적으로 연결합니다.
4. 추가될 행을 검토하고 맞을 때만 적용합니다.

이어붙이기는 열 연결을 추측하지 않으며 두 원본 파일 모두 수정하지 않습니다. 연결하지 않은 대상 필드는 추가 행에서 비어 있습니다.

### 현재 파일과 기준 파일 비교

1. 현재 파일과 기준 파일을 열고 현재 파일을 기준 원본으로 둡니다.
2. **원본 비교**에서 기준 원본을 고릅니다.
3. ID/기준 열을 하나 이상 고르고, 두 파일의 열 이름이 다르면 연결을 추가합니다.
4. 비교할 필드 연결을 추가하고 결과를 검토합니다.

검토는 변경·누락·기준 파일에만 있는 행을 보여 줍니다. 어느 한쪽에 빈 비교 키나 중복 키가 있으면 멈춥니다. 임의의 행을 고르지 말고 원본의 문제를 먼저 해결하세요.

### 참조 파일에서 값 조회

현재 파일을 기준 원본으로, 참조 파일을 다른 원본으로 하여 **열 조회**를 사용합니다. ID/기준 열을 고르고 이름이 다른 키를 연결한 뒤 가져올 참조 필드를 추가하세요. 결과에는 출처가 드러나는 참조 열이 추가됩니다. 일치가 없으면 비어 있으며, 빈/중복 키는 작업을 막습니다.

## 4. 적용·되돌리기·내보내기·선택 저장

모든 작업은 메모리의 결과를 바꾸기 전에 검토 화면을 엽니다. **되돌리기**와 **다시 실행**은 이 세션에서 확정한 작업에 적용됩니다. 검토 화면의 원본 행 정보는 결과 값을 가져온 행까지 추적하는 데 도움을 줍니다.

**내보내기**에서 다음을 고를 수 있습니다.

- **결과 .xlsx** — 현재 결과를 텍스트 셀로 저장한 새 통합 문서. 원본 서식이나 숫자 셀 형식을 보존하는 출력은 아닙니다.
- **결과 .csv** — 현재 결과로 만드는 CSV.
- **원본 / 서식 파일** — 표시될 때만 선택하세요. 선택된 원본에 대해 보호된 출력이며 지원하지 않는 경우에는 제공되지 않을 수 있습니다.

다운로드는 브라우저가 시작합니다. “다운로드를 시작했습니다”는 디스크에 실제 저장됐다는 보장이 아니므로 브라우저 다운로드 목록이나 선택한 폴더를 확인하세요.

**이 기기에 보관**은 선택 사항입니다. 선택 후 **기기 사본 저장**을 누르고, 나중에 **기기 사본 불러오기**로 돌아옵니다. 이 브라우저·이 기기의 IndexedDB에 로컬 프로젝트 사본을 저장합니다. 작업을 공유하거나 백업을 만들지 않으며, 브라우저 저장소를 지우면 보존되지 않습니다. 다른 탭에서 더 새 사본을 저장한 뒤 오래된 사본을 저장하려 하면 최신본을 조용히 덮어쓰지 않고 거부합니다. 새로고침 후에는 이전 세션의 되돌리기 이력이 복구되지 않습니다.

## 5. 레시피를 신중하게 다시 쓰기

작업 이력에서 확정한 작업을 `.sheet-recipe.json` 파일로 저장할 수 있습니다. 임의의 개별 셀 수정은 포함하지 않습니다. 다시 쓰려면 새 원본 파일을 열고 **레시피 불러오기**를 고른 뒤, 저장된 각 원본을 현재의 올바른 원본과 연결하고 재실행 미리보기를 확인하세요. 시트/범위가 달라지거나 열 구조가 맞지 않으면 적용 전 고치세요. 레시피가 바뀐 파일 구조를 억지로 통과시킬 권한을 주는 것은 아닙니다.

## 다른 모드

- `?mode=team`은 기존 팀 화면을 엽니다. 직접 설치한 서버와 PostgreSQL이 있어야 하며 공개 Pages 서비스가 아닙니다. 루프백 전용 가상 시험은 `npm run demo:team`을 실행하고 `TEAM_TRIAL_READY` 뒤 <http://127.0.0.1:3002/?mode=team>을 열어 `samples/team.xlsx`로 시작합니다.
- `?mode=demo`는 이전 가상 데모를 유지합니다. 정적 빌드에서는 실제 파일·계정 정보·Google 승인을 받지 않습니다.

[공개 작업 도구](https://duct-tape2.github.io/sheet-workbench/?lang=ko)는 브라우저 로컬 정적 빌드입니다. 실제 반영된 버전은 [배포 기록](https://github.com/duct-tape2/sheet-workbench/actions/workflows/pages.yml)에서 확인하세요. 회사 기밀이나 개인정보 대신 가상 자료·민감정보를 지운 시험용 사본부터 사용하세요.

## 검증과 호스팅 경계

```sh
npm run check
npm run test:e2e:local
npm run test:e2e:static-demo
```

로컬 리뉴얼에는 로컬 자동·브라우저 테스트 증거가 있습니다. 새 버전을 공개하기 전에는 검사를 다시 실행하세요. 실제 Google OAuth/Picker/쓰기, 실제 메일 전달, Docker·공개 HTTPS, 데스크톱 Excel 재열기, 관리형 팀 서비스는 검증되지 않았습니다. [로컬 검증](LOCAL_VALIDATION.md), [셀프호스팅](SELF_HOSTING.md), [출시 체크리스트](LAUNCH_CHECKLIST.md)를 참고하세요.
